# Дизайн-система OracleAI

## Визуальная позиция

OracleAI — это **тихий ночной ритуал**, а не «игровой автомат предсказаний». Визуальный язык соединяет глубокий космический фон, тёплые световые акценты, тактильные поверхности и ясную редакционную типографику. Пользовательница должна чувствовать атмосферу, но не терять ориентир в навигации, иерархии и действиях.

> Принцип: **«Мистичность задаёт настроение; интерфейс остаётся предсказуемым».**

## Источник токенов и каскад стилей

Первичный источник переменных и базовых правил — [`miniapp/css/00-tokens.css`](../miniapp/css/00-tokens.css). Все новые значения должны быть оформлены как токены или переиспользование существующих переменных, а не как случайные hex-коды внутри экранного CSS. Порядок импорта в [`miniapp/styles.css`](../miniapp/styles.css) обязателен; `15-ritual-redesign.css` — финальный слой, который уточняет продуктовую визуальную систему.[1]

| Уровень | Назначение | Примеры |
|---|---|---|
| Tokens | Цвет, типографика, радиусы, тени, длительности. | Фон, текст, accent, surface, spacing. |
| Shell | Базовый canvas, header, нижняя навигация и safe area. | Ночной фон, app-frame, viewport. |
| Feature | Стили отдельных поверхностей. | Карта, Таро, профиль, чат, совместимость. |
| Ritual redesign | Единое polish-покрытие. | Age-gate, ритуал дня, сезонный блок, языковой picker, motion. |

## Цвет и контраст

Палитра строится вокруг тёмной глубины, а не абсолютного чёрного: это уменьшает визуальную агрессию и даёт место светящимся элементам. Светлые акценты используются для смысла и фокуса, а не как бесконечное украшение.

| Семантическая роль | Использование | Запрет |
|---|---|---|
| **Canvas** | Основной глубокий фон, достаточный контраст с текстом. | Не применять к CTA как единственный индикатор интерактивности. |
| **Surface** | Карточки, sheets, композер, настройки. | Не создавать «стену» из одинаковых рамок. |
| **Primary accent** | Главный CTA, активный tab, фокус ритуала. | Не использовать более одного главного акцента на один экран. |
| **Secondary accent** | Луна, карты, сезонные детали, статус. | Не конкурировать с CTA по яркости. |
| **Text / muted text** | Читаемый заголовок и вторичная поясняющая копия. | Не ставить тонкий muted-текст на активный фон. |
| **Danger / support** | Ошибка, безопасное предупреждение, выход. | Не имитировать «роковую» или тревожную символику. |

Контраст проверяется для текста, иконок и фокуса. Цвет никогда не является единственным носителем состояния: добавляйте подпись, форму, иконку или position change.

## Типографика и копирайтинг

Интерфейс использует короткую выразительную фразу для эмоционального фокуса и спокойный читабельный текст для действия. Заголовок не должен превращать символическую интерпретацию в утверждение факта.

| Элемент | Правило | Пример |
|---|---|---|
| Kicker | Короткий верхний контекст, прописные — только если читаемы. | «ТВОЁ ПРОСТРАНСТВО» |
| Заголовок | Одна понятная мысль, без более чем двух строк на мобильном. | «Сначала — бережная граница» |
| Основной текст | Короткие абзацы, простая лексика, один вывод. | «Заметь, что для тебя важно сегодня.» |
| CTA | Глагол + ожидаемый результат. | «Открыть диалог», «Сохранить мысль» |
| Безопасность | Прямой человеческий язык; не прятать в мелкую сноску. | «Это не медицинская или психологическая помощь.» |

RU и EN — самостоятельные языковые версии, а не пословный перевод. Строки должны тестироваться на переполнение в header, кнопках, tab и settings; не обрезайте безопасные предупреждения многоточием.

## Motion

Анимация усиливает фокус, подтверждает действие и создаёт «ритуальность», но не должна замедлять ежедневное использование. Для интерактивных элементов отдавайте предпочтение `transform` и `opacity`; они меньше затрагивают layout и лучше воспринимаются на мобильном webview.[2]

| Сценарий | Ориентир | Ограничение |
|---|---|---|
| Нажатие кнопки | 100–160 мс, лёгкое уменьшение. | Не задерживать переход или отправку формы. |
| Chip / tab | 150–220 мс, цвет/opacity/transform. | Не использовать только цвет для активного состояния. |
| Sheet / overlay | 200–350 мс, fade + translate/scale от 0.95. | Не запускать параллельно несколько overlay. |
| Появление группы | Stagger 30–80 мс. | Только при первом входе или редкой награде. |
| Декоративная атмосфера | Медленно и негромко. | Отключать для `prefers-reduced-motion`. |

```css
@media (prefers-reduced-motion: reduce) {
  *, *::before, *::after {
    animation-duration: 0.01ms !important;
    animation-iteration-count: 1 !important;
    scroll-behavior: auto !important;
    transition-duration: 0.01ms !important;
  }
}
```

## Telegram Mini App и жесты

Интерфейс mobile-first. Не рассчитывайте на hover и не размещайте основное действие за пределами удобной зоны большого пальца. Свайпы через `14-gestures.js` дополняют, но не заменяют явные действия нижней навигации: жест не должен срабатывать на поле ввода, горизонтальной ленте, picker или прокручиваемой переписке.[3]

Учитывайте safe area, динамическую высоту Telegram WebView и экранную клавиатуру. Композер чата обязан оставаться доступным при изменении `visualViewport`.[4]

## Доступность и QA-инварианты

| Проверка | Критерий готовности |
|---|---|
| Tap targets | Практически нажимаемы одной рукой; соседние действия не конфликтуют. |
| Keyboard | Focus не теряется в modal/sheet; Enter не отправляет незавершённую форму без намерения. |
| Screen reader | У интерактивных иконок есть `aria-label`; декоративный логотип скрыт от чтения. |
| Ошибки | Сообщение на человеческом языке, следующее действие ясно, данные формы не пропадают. |
| Loading | Card/skeleton сохраняет структуру; CTA не вызывает дубликат запроса. |
| Long text | RU/EN, длинное имя и большой системный шрифт не ломают header и карточки. |
| Motion | Включён `prefers-reduced-motion`; некадровая анимация не ухудшает задачу. |
| Безопасность | 16+, память и ограничения сервиса видны до рискованного/персонального сценария. |

## Правило внесения визуальных изменений

1. Сначала определите пользовательскую задачу и состояние, затем выбирайте эффект.
2. Сверьте компонент с таблицей выше и существующими токенами.
3. Добавьте HTML, CSS, `data-act` и обработчик без inline-скриптов.
4. Проверьте 360–430 px viewport, Telegram safe area, клавиатуру, RU/EN и reduced motion.
5. Повышайте cache-busting версию в `index.html` и `styles.css` при изменении клиентского ассета.
