# Онбординг-аудит Mini App (G35)

Аудит по принципу «пользователь дошёл до оплаты, не потерявшись». Файлы:
`miniapp/index.html`, `miniapp/styles.css`, `miniapp/app.js`.

## Что уже хорошо (не трогаем)

- Один экран-хаб «Сегодня» с картой дня и прогнозом сразу — путь к ценности в
  1 экран; таб-бар `#tabbar` с safe-area, blur-стекло, тема под Telegram.
- Состояния ошибок: `toast()` + `reportError()` для всех загрузчиков табов,
  ApiError с человечным `detail` из API (не стек).
- Анимации карт Таро отключаются классом `.calm` (тренетение при медленных
  устройствах уже продуман).
- Лимиты показываются как «пламя» с подписью — игровое ограничение, а не
  дверь в лицо; рядом кнопка «Спросить Оракула» → оплата/Кристаллы.

## Что исправлено в этом проходе

1. **Доступность (a11y)** — `miniapp/styles.css`:
   - `button { min-height: 44px }` — тач-цель не ниже рекомендации Apple;
   - `touch-action: manipulation` — убирает 300 мс задержку двойного тапа;
   - `:focus-visible` — видимый фокус для клавиатуры/свитч-навигации;
   - `@media (prefers-reduced-motion: reduce)` — гасит всю анимацию для
     пользователей, которым движение мешает (вестибулярка).

## Оставленные решения (осознанно)

- **Онбординг в боте, а не в Mini App**: ввод даты рождения через webapp —
  длинный путь с валидацией; в Telegram-чате это 3 коротких вопроса уже есть.
  Mini App стартует сразу с продуктом, детали карты дозаполняются. Менять не
  стали.
- **Цвет фона заливки**: оставлен как есть до прихода фирменных цветов
  (G37-дизайн на бренде). Сейчас грамотно-тёмный, темы не ломает.

## Метрики для UX-контроля (после запуска)

- Доля дошедших от первого /start до первого прогноза (> 60% — ок).
- Доля открывших Mini App повторно на следующей неделе (ретеншен UI).
- Средняя длина до первого рас расклада за Stars (не больше 3 нетапов).
- Тапы «Спросить Оракула» → оплата: конверсия > 2% на активную аудиторию.
