# OracleAI — аудит интерфейса и пошаговый план премиум-полировки (ПК + телефон)

**Дата:** 27 августа 2026 года.
**Область:** Telegram Mini App (`miniapp/`), публичный лендинг (`web/`), админ-панель (`admin/`), все состояния RU/EN, ширины 320–1920px.
**Статус фазы 0 (этот коммит):** выполнены быстрые победы — устранены «тяжёлые» ассеты, навигация получила скользящий индикатор и эффекты, на ПК/планшете приложение выглядит как парящее устройство, точка колокольчика больше не врёт.

---

## 0. Как читать этот документ

Каждая фаза = отдельный, безопасно деплоящийся кусок. Внутри — конкретные файлы, действия и критерий приёмки. Порядок фаз — приоритет: сначала то, что пользователь видит и чувствует как «дорого/дёшево», затем системная гигиена, затем эффекты.

Обозначения: **P0** — критично для премиум-ощущения и стабильности; **P1** — заметная полировка; **P2** — усиление эффектов и масштабирование.

## 2. ФАЗА 0 — Быстрые победы (ВЫПОЛНЕНО в этом коммите)

Цель: максимальный визуальный/производностный эффект минимальным риском.

1. **Премиальная навигация v2** (`miniapp/css/17-premium-shell.css`):
   - скользящий золотой индикатор активной вкладки на пружинной кривой (cubic-bezier(.34,1.3,.5,1)), позиция через `--nav-index`, который выставляет `app.renderNav()`;
   - hover: иконка приподнимается и масштабируется; active: scale(.95); focus-visible: золотой outline 2px;
   - пульсирующее свечение точки колокольчика;
   - навигация — плавающая стеклянная капсула с внутренней подсветкой кромки.
2. **Десктоп/планшет — «парящая рамка»**: при ширине ≥601px `#app-root` получает радиус 34px, тонкую рамку, многослойную тень, внутреннюю атмосферу и ограничение высоты (`min(920px, 100dvh − 56px)`); на ≥1440px по бокам — мягкие аметистово-золотые световые пятна.
3. **−4.8 МБ трафика**: карта дня в CSS переведена с 2.5МБ PNG на 170КБ JPG.
4. **SVG-favicon** вместо 1.4МБ PNG; добавлены `apple-touch-icon`, `preconnect`, `preload` фонового фото.
5. **Честный колокольчик**: точка непрочитанного — один раз в день до открытия панели (флаг `oracle_bell_seen` в localStorage), aria-статус обновляется.
6. **Esc закрывает** sheet инструментов и модалки (ПК + скринридеры).
7. **`<html lang>` синхронизируется** с языком пользователя при старте и при переключении.
8. Бамп cache-busting до `v=96`, гейт дизайн-контракта расширен до 18 CSS-модулей.

**Критерии приёмки (все пройдены):**
- `node --check` по всем JS — OK;
- `scripts/check_design_contract.py` — OK;
- `scripts/check_cache_busting.py` — OK;
- `scripts/check_visual_contrast.py` — все пары ≥ AA;
- ручная проверка: свайпы, переключение табов, чат, модалки на 375/768/1440px.

## 3. ФАЗА 1 — Производительность и гигиена ассетов (P0, ~0.5–1 день)

Цель: первый экран должен появляться за <1.5 c на 3G, отсутствие «миганий».

1. **Удалить из раздачи мёртвые тяжёлые исходники.** `card-art.jpg`, `card-back-alt.png`, `card-face-src.png`, `card-back-src.png`, `tarot-back.png`, `og-src.png` перенести в `design/sources/` (вне `miniapp/img/`) или удалить, если не нужны для генерации. `oracle-mark.png` пересохранить в 256×256 (~120 КБ) — он нужен только как apple-touch/OG fallback.
   - *Проверка:* `du -sh miniapp/img` < 8 МБ (сейчас 26 МБ), `grep -r` не находит ссылок на удалённые файлы.
2. **Минификация и объединение.** Ввести минимальный сборочный шаг (esbuild для JS, lightnincss/cssnano для CSS) без переезда на фреймворк:
   - вход — текущие файлы в том же порядке (порядок уже зафиксирован `check_design_contract.py`);
   - на выходе — `app.min.js` + `app.min.css` с content-hash в имени, `index.html` ссылается на хешированные файлы;
   - dev-режим оставляет несжатые файлы.
   - *Альтернатива без сборки:* включить сжатие на статике (`gzip_static`/brotli в nginx, FastAPI `GZipMiddleware` для `/static` — замерить, не ломает ли это Telegram WebView) и заменить `@import` на один `<link rel="stylesheet">` с выровненным порядком файлов.
   - *Проверка:* Lighthouse Performance ≥ 90 в эмуляции мобильного; число запросов статики ≤ 6.
3. **Preload ключевых ассетов первого экрана:** шрифт PJS latin/cyrillic, `card-back.jpg` (для карты дня), аватары агентов первого экрана — `<link rel="preload" as="image">`; для всего остального сохранить `loading="lazy"`.
4. **Загрузка 17 JS с `defer`** (скрипты уже в конце тела — проверить порядок при defer; при объединении вопрос отпадёт).
5. **Картинки агентов и Таро:** перевести в WebP/AVIF с `<picture>`-фолбэком или хотя бы пережать JPG до качества 80 и ширины ≤640 (карты показываются максимум ~160px шириной на телефоне; 78 файлов Таро по ~90 КБ → ~30 КБ каждый экономии ~4.5 МБ).
6. **Фон:** `bg-cosmos.jpg` 872×1300 — добавить srcset по ширине вьюпорта (мобайлу хватит 720px версии ~25 КБ), оставить текущий для десктопного frame.

**Критерий приёмки фазы:** сумма критических ресурсов первого экрана < 600 КБ gzip; LCP < 2.0 c; CLS = 0 (изображения с заданными размерами/aspect-ratio); ни одного 404 в Network на всех экранах.

## 4. ФАЗА 2 — Консистентность компонентов и состояний (P0, ~2–3 дня)

Цель: убрать визуальный «шум» — то, из-за чего продукт читается как самодельный.

   - После каждого переноса поднимать гейты и визуальный capture. **Правило: один компонент — одно место определения.**
2. **Токенизация «магических значений».** Ввести в `00-tokens.css` недостающие ступени и заменить хардкод:

3. **Завершить sigil-набор.** Добавить в `sigilIcon()` иконки: close (✕), chevron-up/down/right, sunrise/notification, check, arrow-send, refresh/retry, lock (память), language. Заменить glyph-контролы на них. Emoji оставить только как **контент** (карты, знак дня), не как кнопки.

**Критерий приёмки:** `visual_qa_capture.py` показывает 0 пиксельных регрессий на 375/768/1440 (сравнение с эталоном фазы 0); не осталось компонента с двумя определениями базовых стилей; ручной прогон всех состояний loading/empty/error.

## 5. ФАЗА 3 — Десктопный layout по-настоящему (P0/P1, ~2 дня)

Цель: на ПК продукт должен выглядеть как продуманное desktop-приложение, а не «телефон в браузере».

1. **Закрепить frame как точку позиционирования.** Все оверлеи (`#app-modal`, `#intro`, `#age-gate`, `#chat-guide`, `.tool-expand`) рендерятся внутри `#app-root` (сейчас они на `document.body` — на ПК при парящем frame перекрывают весь экран).
   - В `showModal()`/`openBell()`/`showAgeGate()`/`maybeIntro()`/`maybeChatGuide()` монтировать в контейнер `#app-root` (или в `#app-overlays` внутри него); CSS `position: absolute; inset: 0` + скругление по frame.
   - *Проверка:* на 1440px затемнение модалки не выходит за рамки устройства; sheet инструментов скруглён по нижней кромке frame.
2. **Адаптивная вёрстка внутри frame на ширине ≥560px (планшет/ПК):**
   - экран чата: двухпанельный режим — слева узкая колонка агентов (аватар + имя + последнее сообщение, ~150px), справа диалог; на мобильном — как сейчас (агенты через табы сверху);
   - на главной: `dock-grid` агентов в один ряд более крупных карточек; лунная неделя — в две колонки;
   - модалки: max-width 430px по центру frame, не вьюпорта.
3. **Клавиатурные сценарии ПК:**
   - `1/2/3` или `Alt+←/→` — переключение разделов;
   - `/` или `Ctrl+K` — фокус в поле ввода чата;
   - `Esc` — закрыть sheet/модал/выйти из чата (добавлено частично в фазе 0);
   - подсказки клавиш показывать в `title`/тултипах только на устройствах с мышью (`@media (hover: hover)`).
4. **Hover-состояния для мыши** на всех интерактивных карточках (агенты, шаги ритуала, дни луны, карточки истории): лёгкий подъём + золотая кромка; на тач-устройствах hover-эффекты отключать (`@media (hover: none)`), чтобы не «залипали».
5. **Курс-индикатор и заголовок окна:** `document.title` обновлять по разделу («OracleAI · Диалоги»); на ПК в шапке frame можно показать «оконные» точки-декорации? — нет, это противоречит бренду; вместо этого — тонкая золотая полоска-блик сверху frame как «свет студийного софита».

**Критерий приёмки:** на 768/1024/1440/1920 ни один элемент не выходит за frame; весь основной сценарий (выбор агента → вопрос → ответ → инструменты → профиль) проходится с клавиатуры; Tab-порядок логичен.

## 6. ФАЗА 4 — Доступность и локализация (P1, ~1.5–2 дня)

1. **Доделать i18n жёсткого русского текста:** intro-слайды `maybeIntro` (3+1 слайд), чат-гайд `maybeChatGuide` (3 шага), контент `openBell` (Сегодня, «Утренний прогноз в боте», вкл/выкл, пояснение), aria-строки в `renderFrame` (частично сделано), кнопка «Пропустить/Дальше/Начать», age-gate уже на русском — вынести в словари `I18N/HOME_I18N`.

2. **Модалки как диалоги:** `role="dialog"`, `aria-modal="true"`, `aria-labelledby` на заголовок; **ловушка фокуса** (Tab циклится внутри), **возврат фокуса** на триггер после закрытия; закрытие по Esc (сделано) и по клику на маску (есть) с сохранением фокуса.
3. **Live-регионы для чата:** `aria-live="polite"` на ленту ответов (ответ ассистента зачитывается), статус `busy` при отправке; у тултипа-индикатора «печатает» — роль `status`.

**Критерий приёмки:** полный проход только с клавиатуры по сценариям; VoiceOver/TalkBack прогон 3 ключевых сценариев (онбординг, чат, смена языка); 0 безымянных focusable (гейт capture).

## 7. ФАЗА 5 — Премиум-эффекты и микроанимации (P1, ~2–3 дня)

Цель: «вау» без ущерба читаемости и скорости. Все эффекты — на `transform/opacity`, уважать `prefers-reduced-motion`.

1. **Staggered-появление контента экранов:** карточки главной/хаба появляются каскадом по 40–60мс (анимация `rise-in`: opacity + translateY(10px) + лёгкий scale). Только при первой отрисовке экрана, не при каждом ре-рендере.
2. **Сообщения чата:** вход нового пузыря — мягкий slide-up + fade; у ответа агента — лёгкое «проявление» текста по мере стриминга (если стриминг есть; если нет — единый fade); отправка — сообщение «всплывает» из композера с движением к ленте.
3. **Карта дня:** переворот карты — добавить блик, проходящий по карте при перевороте (псевдоэлемент с градиентом, двигается за поворотом); у карты в ленте Таро — тень, меняющаяся при наведении/нажатии.
4. **Параллакс глубины на ПК:** слои фона (звёзды/туманности/силуэт) реагируют на движение мыши с разным коэффициентом (0.5/1/1.5% смещения), через `requestAnimationFrame` и CSS-переменные; на мобильном — лёгкий параллакс от скролла (уже есть, усилить расслоение по слоям).
5. **Мягкий ripple на кнопках/чипах:** расходящийся круг от точки касания в цвет акцента (surface ink), 300мс; на ПК — только при клике, не при hover.
6. **Haptic-feedback по всем действиям:** `haptic('light')` на табы/чипы, `haptic('success')` на завершённые действия (ритуал, отправка), `haptic('medium')` на открытие sheet — единая обёртка, проверить все вызовы.
7. **Единый язык свечения:** CTA — золотое свечение при hover/focus; активные агенты — свечение цветом агента; фокус ввода — тонкое кольцо; убрать случайные `box-shadow` с размытием >40px в не-декоративных местах.
8. **Прогресс ритуала на главной:** полоска 0/2 → 2/2 — анимировать заливку (transition ширины 600мс с задержкой), завершённый шаг — галочка с чек-маршем (масштаб + лёгкий поворот).
9. **Прелоадер первого запуска:** звёздная сигил-печать, собирающаяся из лучей (600–900мс), вместо пустого экрана до загрузки `/api/me`.

**Критерий приёмки:** при `prefers-reduced-motion` все эффекты отсутствуют/мгновенны; ни одна анимация не двигает layout (только compositor-свойства); 60fps на mid-range Android (проверка через Performance в DevTools, long frames < 50мс).
