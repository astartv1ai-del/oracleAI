## Checks

| Область | Метод | Статус |
|---|---|---|
| Секреты | `.env` в .gitignore; в git только `.env.example` | ✅ |
| dev-резерв | `?dev_user` работает только при `DEV_MODE=1`; на проде за-фолл to Telegram-подпись (`deps.py:90`) | ✅ |
| SQL-инъекции | Все значения через `?`-плейсхолдеры; динамические части (`{keys}`) — whitelist-столбцы из внутренних констант, не ввод пользователя | ✅ |
| XSS (miniapp) | Пользовательский контент обёрнут `esc()`; inline-хендлеров нет — data-act делегирование (CSP) | ✅ |
| CSP | Dev-строгий CSP отключён (CDN+inline) — известное ограничение G24 | ⚠️ на prod поставить `DEV_MODE=0` + строгий CSP |
| Авторизация | Изменений нет; endpoints покрыты существующими зависимостями | ✅ |

## Findings
- **Ноль новых** уязвимостей, внесённых этим пассом.
- Единственный исправленный backend-баг (compat 500) — корректное поведение Row, не уязвимость.

## Рекомендации (не блокирующие, для прод-деплоя)
1. Prod: `DEV_MODE=0` — вход строго через подпись Telegram.
2. Prod: включить строгий CSP (при деплое статики без CDN).
3. Не логировать секреты: в `app/api/main.py:54` предупреждение DEV_MODE логируется без пароля — ок.
4. Перед публичным запуском — ревью токенов/субподписок в панели админа (вне скоупа этого пасса).
